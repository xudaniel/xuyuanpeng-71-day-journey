# 71-Day OS · Mobile-first implementation

`os.html` is a local-first execution surface for the 71-day journey. It intentionally does not embed private trip content in the repository.

## What is implemented

- Canonical public seed data in `data/journey.json`, with stable stage IDs and validation helpers.
- Mobile quick editing for current-stage city/start/end dates with impact preview, history and one-tap undo.
- AES-GCM encrypted browser persistence using a password-derived PBKDF2-SHA-256 key.
- Encrypted portable backup, restore preview, older-backup warning and explicit restore confirmation.
- Schedule feasibility radar for time overlap, cross-location buffer, flights and trains, with time-zone-aware comparisons and explicit risk overrides.
- Relationship CRM with stable person/organization IDs, alias duplicate detection, open loops and interaction timeline.
- Mobile-first PWA shell with offline asset caching after the first successful load.

## Privacy model

The repository contains only the application code and the already-public-safe journey seed. Personal contacts, notes, actions, meetings and overrides entered in `os.html` are encrypted before they are written to browser storage. The unlock password is held only in memory for the active page session.

The existing `private.html` encrypted itinerary is deliberately not regenerated by this change, because its encryption password is not stored in the repository. That avoids weakening the existing security boundary.

## Validation

Run:

```bash
node --test tests/os-core.test.mjs tests/storage.test.mjs
```

The tests cover canonical seed validation, stage impact/undo, conflict detection, relationship open-loop classification and encrypted backup round-trips.
