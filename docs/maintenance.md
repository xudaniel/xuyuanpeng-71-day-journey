# 技术与维护说明

面向移动端设计的行程进度与执行看板。项目提供“公开安全分享版＋加密完整版＋本机执行 OS”三个入口，在便于查看与转发的同时，尽量减少敏感信息暴露。

## 版本说明

| 版本 | 入口 | 适用场景 | 信息范围 |
| --- | --- | --- | --- |
| 手机安全分享版 | `index.html` | 日常查看、对外转发 | 输入访问密码后展示概览与脱敏内容 |
| 加密完整版 | `private.html` | 本人及授权人员使用 | 输入独立访问密码后，在浏览器本地解密完整行程 |
| 手机执行 OS | `os.html` | 本机执行、交通确认与跟进 | 从基础行程加载路线，个人记录以本机自设密码加密 |

当前 GitHub Pages 入口：

- 公开入口：<https://xudaniel.github.io/xuyuanpeng-71-day-journey/>
- 完整版入口：<https://xudaniel.github.io/xuyuanpeng-71-day-journey/private.html>
- 手机 OS：<https://xudaniel.github.io/xuyuanpeng-71-day-journey/os.html>

访问密码不会写入本仓库，也不应通过公开渠道发送。

## 安全设计

- 公开版与完整版分别使用 **AES-256-GCM** 加密，密码与密文互相独立。
- 密钥由访问密码通过 **PBKDF2-SHA-256（310,000 次迭代）** 派生。
- 解密仅在访问者的浏览器内完成，页面不会上传或保存密码。
- 公开版已移除确认号、交通班次、详细地址、联系人及其他敏感明文。
- 页面不依赖后台数据库，不设置账户，不包含统计追踪代码。

## 使用与维护

1. 对外只分享公开入口。
2. 完整版链接与访问密码应分开传递。
3. 行程内容变化时，按下方“行程同步范围”逐项更新。完整版在解密后依次应用9月14日和9月15日路线修订，最终显示9月30日—10月7日抚州、10月8日返深；保留原密码和密文。
4. 怀疑密码泄露时，应立即更换密码并重新加密发布。
5. 更新前检查源码，确认敏感信息没有以明文形式出现。

## 行程同步范围

当前基准：2026年9月15日，71天／12阶段／14城市节点；9月13—29日深圳、9月30日—10月7日抚州、10月8—22日深圳，10月23日起日本及之后安排不变。

1. 更新 `data/journey.json` 的日期、城市和摘要；尽可能保留既有稳定 ID，新阶段使用独立 ID。
2. 解密并修改公开行程，再重新加密到 `index.html`；核对日期、路线节点、阶段计数及日历导出。
3. 同步 `private.html` 解锁后的路线修订；原有会面资料只按已确认的改动处理，阶段日期不等于会面日期。
4. 更新 `README.md`、`docs/itinerary.md`、`docs/itinerary-overview.svg`、受影响的参访卡／成果页和跟进清单；过时方案仅放在明确标注的历史记录中。
5. 更新 `docs/changes.md`；涉及已缓存的应用或基础行程时递增 `sw.js` 缓存版本。
6. 运行行程验证与必要的浏览器检查，核对各自然日唯一归属以及变更前后的转场边界。

OS会加载新的基础行程；用户已保存的阶段覆盖、个人活动及备份保留原值。若本机阶段曾手动调整，需在设置中核对它与基础行程的差异。维护仓库不会改写用户设备上的加密记录。

## 重要限制

本项目的密码页属于浏览器端加密访问，不等同于服务器账户系统。公开 GitHub 仓库的历史提交仍可能保留过去发布过的内容；如需彻底移除旧敏感资料，必须另行清理 Git 历史、旧部署及相关缓存。

原应用版本已通过 PR #2 合并并发布。9月15日已同步公开行程、OS基础数据与完整版的解锁后路线（9月30日至10月7日抚州）。完整版迁移失败时不展示旧路线，并提示查看公开版。

## 更新加密公开版

维护者在本机设置 `PUBLIC_SHARE_PASSWORD` 环境变量，用 `node scripts/share-page.mjs decrypt < index.html > test-results/public-edit.html` 解密，修改本机文件后，用 `node scripts/share-page.mjs encrypt < test-results/public-edit.html > test-results/index.next.html` 重新加密，再替换 `index.html`。不要把明文文件提交到仓库；`test-results/` 已被忽略。

运行 `node --test tests/itinerary.test.cjs`（需要同一环境变量）可验证解密后的行程。访问密码不保存在浏览器中，刷新后需要重新输入。此入口不限制公开仓库历史或独立的 OS 行程数据访问。
