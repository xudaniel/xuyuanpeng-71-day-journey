# 七十一日执行中心

解锁 `private.html` 后，今日页面首先显示执行中心。公开入口保留行程概览和登录入口，不读取个人执行记录。

## 每日使用

1. **今日队列**：按 P0（今天必须做）、P1（今天应该做）、P2（可选）排列。每级内先逾期，再按截止时间排列。点击统计卡可查看对应事项；同一行动即使同时是跟进和 Waiting For，也只出现一次。
2. **待办与跟进**：新增行动、选择优先级、安排日期、负责人及目标日期；可关联会面或交通。等待反馈时填写“等待谁、等待什么、下次跟进”。完成时填写交付／确认记录，取消时填写原因。
3. **会面**：准备清单可标记完成或不适用（需原因）。准备度按适用项计算。查看缺项、打开已有准备卡，然后显式标记准备就绪。
4. **成果**：记录实际发生时间，再分别填写成果摘要、对方陈述、现场观察、个人判断和出处。创建后续行动或明确记录无需跟进，才能进入跟进阶段。
5. **关闭**：所有关联行动（含等待反馈）已完成或取消后，手动关闭会面。新增或重新打开关联行动会重新打开会面。阶段更正需要原因，并保留记录。
6. **交通住宿**：默认显示未来七天未确认项目；当日及确认截止已到期的安排进入每日提醒。确认或取消安排会同步处理其专属确认行动。普通关联待办的完成不会自动确认预订。

阶段为 **Planned → Prepared → Completed → Notes → Follow-up → Closed**。已经发生却没有登记准备的会面可补录实际完成，但必须说明原因，不会虚构准备记录。阶段核验与执行中心分别记录；日期经过不代表实际完成。

## 日期与初始资料

- 自然日使用 Asia/Shanghai；仅日期的截止事项在该日结束后逾期。具体时刻须包含 UTC 偏移，如 `2026-09-22T14:00+08:00`。界面上的计划会面时间使用所选当地时区。
- “下一场会面”显示有计划日期且尚未完成的下一场会面；日期未知的会面在“日期待定”中复核，不会猜测日期。
- 首次使用连接现有五家企业的准备／成果文档。公开文档中日期不确定的会面保持日期待定，保留已知阶段范围。已有问题草稿不自动算完成，也不自动创建承诺。
- 根据解锁后的行程阶段生成交通及住宿**待核对记录**，初始状态为未核验。日期是阶段起点，标题明确标注待核对；这不代表该日有预订。用户须核对日期、拆分实际交通／住宿或填写取消原因。
- 后续人工编辑的执行记录是本机唯一可编辑来源；原 Markdown 模板是参考资料，不自动回写，也不与设备记录双向同步。
- 进入、退出 71 天范围时，执行中心显示尚未开始／已结束，逾期事项仍可处理。旧行程卡保留其原有范围内日期浏览行为。

## 保存与备份

记录仅保存在当前浏览器／设备的 `journey-execution-encrypted-v1` 中。PBKDF2-SHA-256（310,000 次，随机盐）派生独立 AES-256-GCM 密钥；每次保存使用新的随机 IV。密码和密钥不写入存储。保存成功才提交界面状态；失败保留输入并明确提示。另一窗口修改记录后，旧窗口需要重新解锁，不能覆盖更新。

使用“导出加密备份”定期保存副本。恢复时上传该文件并输入**备份保存时的密码**，确认替换当前记录。清除浏览器数据、换设备或更换访问密码前，应先导出备份。更换密码后若旧设备记录无法解锁，请保留加密记录，在原密码仍可使用的入口导出；在新设备／浏览器解锁新入口后，用原密码恢复备份，再保存为新密码加密的记录。没有旧密码无法恢复旧记录。

安全模式移除执行中心的私密 DOM；重新解锁前不会读取新的私密视图。打印和既有日历导出不包含执行记录。锁定会重新载入密码页；浏览器返回缓存也会重新锁定。

## 维护与验证

网站仍为静态文件，无运行时依赖、账户、服务器数据库或发送通知服务。

- `app/model.mjs`：日期、提醒、优先级、准备度、会面状态规则及关联行动。
- `app/vault.mjs`：设备加密记录、备份及并发写入检查。
- `app/ui.mjs` / `app/execution.css`：移动界面及事件处理。
- `app/boot.mjs`：解锁后的初始化。
- `private.html`：只修改登录外壳，解密成功后加载执行中心。原行程密文、盐、IV 和密码机制保持不变；不需要把完整行程提交为明文。

开发使用 Node 24 和 pnpm 11：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm exec playwright install chromium
pnpm test:browser
```

浏览器检查可通过 `BROWSER_EXECUTABLE` 指定已有 Chromium 可执行文件。可选 `PLAYWRIGHT_MODULE` 指向预装 Playwright 的入口。生产部署不需要安装这些开发工具。

自动检查包括日期边界与时区、去重与排序、Waiting For、准备度、完整生命周期、无跟进路径、交通状态、加密与错误密码、备份恢复、存储失败和跨窗口冲突。浏览器测试用**临时生成的合成密文**运行生产登录代码，不使用或解密真实私人行程；验证移动界面、加密后刷新、完整工作流、安全模式和原日历导出。真实密码及真实密文的人工登录检查仍须由持有密码的人完成。
